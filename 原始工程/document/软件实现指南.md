# GD32F103C8T6直接测周法频率计——软件实现指南

版本：v1.0  
日期：2026-09-20  
状态：实现设计，尚未编写、编译或上板验证固件。项目目录当前为空，以下目录和接口均为建议，不表示已有实现。

## 1. 目标与已确定方案

主控使用GD32F103C8T6，采用外部10MHz时基、定时器输入捕获和多周期平均测量周期，再计算频率。

- 周期范围：10μs～10s，对应100kHz～0.1Hz。
- 有效计数时基：10MHz、1MHz、100kHz，按键切换。
- 支持单周期、多周期、连续测量、保持和统计。
- 显示周期、频率、时基、平均周期数和测量状态，提供至少8位数字的排版空间。
- 删除Si5351及其对外信号发生接口，改用独立10MHz有源晶振。
- 第一版采用裸机主循环，不引入RTOS、无线通信或APP。
- 显示层不绑定具体屏幕，兼容后续选择OLED或原图ST7735 TFT。

“显示8位”不等于“8位有效精度”；10MHz档的计数步长为0.1μs，不等于任何输入条件下绝对误差都小于0.1μs。1MHz、100kHz档单周期步长分别为1μs、10μs。如果验收要求所有时基档均达到0.1μs，需要单独澄清，不能通过增加显示小数位解决。

## 2. 软件依赖的硬件条件

### 2.1 引脚建议

默认映射、不启用TIMER1重映射：

| 用途 | GD32引脚 | 外设功能 | 说明 |
|---|---|---|---|
| 标准时钟输入 | PA0 | TIMER1_ETI | 接10MHz有源晶振OUT |
| 被测边沿输入 | PA1 | TIMER1_CH1 | 接比较器输出的3.3V逻辑信号 |
| 调试下载 | PA13、PA14 | SWD | 保留 |
| 系统时钟 | 原核心板晶振引脚 | HXTAL | 不与新增10MHz时基混用 |

原参考原理图的PA1连接YELLOW_LED，必须将该LED移走。原图HIGH_FREQ、LOW_FREQ分路不能直接沿用为这里的时基与捕获接线。

GD32的TIMER1与STM32的TIM2在本方案中对应；GD32的CH1对应STM32的CH2。编号不相同，不能机械复制STM32代码。

### 2.2 输入与供电

- 10MHz有源晶振选择3.3V供电、CMOS方波输出，按实际器件连接使能脚。
- 时钟电源就近100nF去耦；OUT走线短，预留串联阻尼电阻位置。
- 外部被测信号先经过保护、衰减/电平平移、缓冲及比较器，不直接接PA1。
- 0.1Vpp触发、5Vpp输入范围、约1MΩ输入阻抗和过压保护属于模拟电路指标，软件不能补救不合格的前端。
- 0.1Hz输入优先使用直流耦合；输入直流偏置允许范围须另行定义。

## 3. 两路信号分别做什么

```text
10MHz有源晶振 → PA0/ETI → 外部时钟通路 → PSC → 16位CNT
                                                           │
被测信号 → 比较器 → PA1/CH1 → 上升沿捕获 ───────────────────┘
                                      把CNT锁存到捕获寄存器
                                                ↓
                                  中断或DMA获取捕获记录
                                                ↓
                                    时间差 → 周期、频率
```

外部时钟驱动硬件计数；更新中断只累计溢出。捕获动作由硬件完成，CPU进入中断后读取锁存值，不能改为读取当时的CNT。

## 4. 时基设置与公式

ETI输入侧预分频关闭，时基切换使用计数预分频寄存器PSC。不要混淆ETI预分频、计数PSC和捕获预分频。

| 时基 | PSC值 | 计数步长 | 16位回绕时间 |
|---|---:|---:|---:|
| 10MHz | 0 | 0.1μs | 6.5536ms |
| 1MHz | 9 | 1μs | 65.536ms |
| 100kHz | 99 | 10μs | 655.36ms |

公式：

```text
counter_hz = reference_hz / (PSC + 1)
单周期：period_s = delta_ticks / counter_hz
多周期：period_s = total_ticks / (N * counter_hz)
频率：frequency_hz = N * counter_hz / total_ticks
```

N个完整周期需要N+1个边沿。内部计算先转换为double或使用足够宽的整数，避免整数截断和乘法溢出；total_ticks为0时丢弃结果。

reference_hz默认10000000.0，可由校准得到实际参考值。若用已知周期T_ref校准，跨越N个周期得到total_ticks，则：

```text
reference_hz = total_ticks * (PSC + 1) / (N * T_ref)
```

独立参考仪器必须比待校准时基更准确。

## 5. 初始化顺序

1. 使用GD32F10x对应的启动文件、设备头文件和标准外设库建立工程；确认64KB Flash、20KB SRAM及链接设置。
2. 初始化系统时钟并更新软件时钟变量。CPU可以用独立系统时钟运行；测量计数源是PA0上的10MHz。
3. 开启GPIOA、TIMER1以及所需复用功能时钟，配置PA0、PA1为对应输入用途，保持默认映射。
4. 停止TIMER1，暂时关闭捕获、更新中断及DMA请求。
5. 设置向上计数、自动重装值65535、PSC为选定值。
6. 选择ETI外部时钟通路：上升沿、ETI不分频、数字滤波初始关闭。保持外围时钟足够高以满足同步采样和外部时钟限制。
7. 配置CH1直接输入捕获：上升沿、捕获不分频、初始关闭滤波。调试噪声时再评估滤波对最短脉冲的影响。
8. 产生更新事件使预分频生效；随后清零计数，按手册清除更新、捕获及过捕获等标志。
9. 清零软件溢出计数和测量上下文，配置NVIC。
10. 开启更新中断；选择捕获中断后端或DMA后端。
11. 开启捕获与计数，进入等待首个边沿状态。

GD32将ETI的专用外部时钟通路称为外部时钟模式1；不要直接照搬STM32的模式编号。具体库函数、枚举和标志清除语义，实施时必须与所用GD32F10x库版本核对。

CPU外设总线时钟仍必须开启。外部时钟模式不意味着定时器脱离芯片内部同步电路独立工作。

## 6. 第一阶段：捕获中断实现

先用低频方波完成该阶段，再扩展高频DMA。

```c
/* 算法伪代码；timestamp由底层完成溢出修正，不是直接读取CNT。 */
void on_capture(uint64_t timestamp)
{
    if (!have_start) {
        start_tick = timestamp;
        have_start = true;
        intervals = 0;
        return;
    }

    intervals++;
    if (intervals == target_n) {
        uint64_t total_ticks = timestamp - start_tick;
        publish_raw_result(total_ticks, intervals, config_epoch);

        /* 当前结束边沿也是下一组的起点。 */
        start_tick = timestamp;
        intervals = 0;
    }
}
```

中断中只做时间戳、计数、状态和原始结果发布；主循环计算浮点结果、更新统计并刷新显示。边沿中断与更新中断共用该定时器中断入口时，应统一处理，不建立相互独立且顺序不明的两套溢出逻辑。

## 7. 16位溢出扩展：长周期关键

### 7.1 基本方法

更新标志表示发生了更新事件。正常自由运行时，每次从65535回到0，软件累计一次溢出：

```text
timestamp = (overflow_count << 16) + capture_value
delta_ticks = end_timestamp - start_timestamp
```

使用64位扩展运算。在10MHz档，10秒对应100000000个计数：

```text
100000000 = 1525 * 65536 + 57600
```

该分解假设计数从0开始；任意起点均使用两个扩展时间戳相减，不能只统计两边沿之间看到了几次溢出。

### 7.2 同时出现捕获与更新标志

| 事件顺序 | 捕获值示例 | 应使用的软件高位 |
|---|---:|---|
| 先捕获，后溢出，更新尚未处理 | 65530 | 原overflow_count |
| 先溢出，后捕获，更新尚未处理 | 5 | overflow_count + 1 |

一种可用判定是：读取同一轮状态快照；如果有待处理更新且捕获值小于32768，则该捕获采用high+1；否则使用原high。然后对该快照中的更新事件累计一次。

成立条件：

- 从事件发生到状态/捕获读取完成的最长延迟小于半个回绕周期；10MHz档为3.2768ms。
- 同一更新事件不会被另一个处理路径提前累计。
- 捕获值没有被后续捕获覆盖；必须检查过捕获标志。
- 状态快照、捕获读取与标志清除遵守手册规定。读取过程中产生的新事件不能被不加区分地清掉。

不要将“读状态—读捕获—清所有标志”写成未经验证的固定模板。正式驱动要核对读捕获寄存器是否会清标志、写0清除位的语义，并对新增事件重新读取状态处理；禁止以危险的读改写方式清除整个状态寄存器。

这份指南定义算法和约束，不提供未经库版本核实的可直接复制ISR。

### 7.3 防止漏溢出和损坏结果

更新标志不是事件队列。中断被屏蔽20ms期间可能发生多次回绕，却只留下一个标志，之后无法仅凭它恢复次数。

- 不在中断中刷屏、阻塞串口、等待按键或执行Flash擦写。
- 捕获/更新中断优先级高于显示和普通通信，控制所有临界区长度。
- 过捕获、已知超时延迟或计数连续性丢失时，废弃当前测量组并重新同步，不能继续发布看似正常的值。
- 独立系统节拍可用于延迟和超时监测，但不能保证事后识别所有漏计情况；最坏延迟必须实测并从设计上约束。
- 更新标志也可能由初始化的软件更新产生，启动前必须清理。

## 8. 高频后端：DMA连续捕获

100kHz每秒产生100000次捕获，不应在没有性能验证的情况下承诺每边沿中断能够稳定运行。

### 8.1 模差算法

在相邻真实捕获间隔严格小于65536个计数、且无丢样时：

```c
uint16_t delta = (uint16_t)(current_capture - previous_capture);
total_ticks += delta;  /* total_ticks为64位 */
```

模差允许跨越一次计数器回绕，但不允许相邻样本间隔达到或超过一个完整回绕时间，也不允许漏掉边沿。

DMA保存的是16位捕获值；禁止在DMA块结束后给每个历史值拼接“当前overflow_count”，也禁止只用首尾16位数直接相减计算跨越多轮的时间。

### 8.2 缓冲与处理

- 建议从256个uint16_t的循环缓冲开始，占512字节。
- 使用半传输和全传输事件，处理已完成的半区，另半区继续接收。
- 100kHz时每128个样本仅间隔1.28ms；已完成半区必须在再次被DMA覆盖前处理完或复制到有界队列。
- 队列满、处理落后、DMA错误和捕获覆盖均计入诊断并废弃测量组。
- 跨半区、跨整块保留previous_capture，以免漏掉边界上的一个周期。
- DMA中断只做必要搬运/计数，耗时显示不得影响缓冲消费期限。

### 8.3 切换与慢信号回退

初始用中断后端探测，确认相邻计数差有充足余量且频率较高后，再切到DMA。模式切换后丢弃首个孤立样本，重新建立测量起点。

必须考虑从100kHz突然降为0.1Hz：DMA模差无法表示此时的长间隔。设置独立系统时间监测、保守的样本进度检查和最大允许间隔；失去高频连续性立即废弃DMA测量组，回到长周期捕获模式。不得仅因某次16位模差较小，就判定输入仍然很快。

初始参考门槛可取：连续若干周期的计数差小于8192后才允许进入DMA；具体进入频率、退出期限及DMA剩余计数轮询间隔根据实测中断负荷确定。退出监测时限应明显小于半个回绕周期，并为首次不完整缓冲留出正确处理逻辑。

本阶段必须验证输入突变、停止及缓冲边界；完成中断阶段不等于完成100kHz全范围验收。

## 9. 测量状态与按键

### 9.1 状态

| 状态 | 含义 | 主要转移 |
|---|---|---|
| WAIT_FIRST | 等待首个边沿 | 捕获后进入MEASURING |
| MEASURING | 已有起点，累计周期 | 达到N后发布结果并继续测量 |
| HOLD | 显示冻结 | 解除后清上下文重新测量 |
| NO_SIGNAL | 超时未获有效边沿 | 新边沿到来后重新建立起点 |
| ERROR | 过捕获、DMA丢样等 | 清理后重新同步 |

结果有效性独立于状态保存：等待下一组时可以显示上次有效值，但必须显示结果年龄或“等待更新”，不能将旧值伪装成新结果。

### 9.2 超时与刷新

- 首次等待允许超过20s，例如22s，覆盖10s周期从任意相位启动的等待。
- 捕获首边沿后，边沿间超时可设12s，为10s周期留余量。
- 超时由独立系统节拍驱动，不使用测量计数器作为唯一计时源，以免10MHz时基断开后超时也停止。
- 多周期测量按“最后边沿时间”检查无信号，不能用固定总等待时间误判正常长窗口。
- 屏幕约5Hz刷新，测量结果按实际产生速度更新；两者分离。
- 时基断开可通过独立时间窗口检查计数器活动性作为辅助诊断，避免固定采样相位混叠；不将其当作精确时基校验。

建议按键：时基、单/多周期与N、运行/保持。按键使用系统节拍消抖，不阻塞延时。

### 9.3 切换时基

停止捕获和DMA请求 → 停止计数 → 修改PSC → 更新装载 → 清标志和计数 → 清缓冲、溢出及平均上下文 → 增加配置版本号config_epoch → 重启。

结果携带config_epoch；主循环丢弃不属于当前配置的结果，避免把旧档计数按新档频率换算。

## 10. 多周期平均与统计

单周期N=1；手动多周期建议N=10、100、1000；自动模式可使用更大的上限，例如10000，且必须流式累计，不保存所有边沿。

```text
N = clamp(round(target_window_s / estimated_period_s), 1, N_max)
```

target_window_s可取0.1s；若单周期大于窗口，则N=1。N仅在测量组边界更新。100kHz时取N=10000，对应约0.1秒窗口。

- 平均周期采用总计数除以N；频率为平均周期的倒数。
- 最大/最小/平均统计必须声明对象。第一版统计“每组输出的平均周期”，不冒充逐周期抖动统计。
- 如需逐周期抖动分析，另外逐周期累计统计，并说明时基量化和输入触发噪声会混入结果。
- 时基、N或模式改变后清空统计，避免混合不同条件的数据。

## 11. 推荐代码组织与并发规则

```text
Bsp/bsp_clock.c          系统时钟
Bsp/bsp_capture.c        TIMER1、更新/捕获中断、DMA、时间戳
Bsp/bsp_keys.c           按键扫描
Bsp/bsp_display.c        屏幕驱动适配
App/freq_meter.c         测量状态机、N选择、周期/频率计算
App/period_stats.c       统计
App/ui.c                 页面、单位及状态
App/main.c               非阻塞主循环
```

建议原始结果至少包含：total_ticks、period_count、config_epoch、有效性/错误标志。使用有界结果队列或有明确覆盖策略的邮箱；队列满时记录丢弃次数。

中断与主循环共享变量可按需要使用volatile，但volatile不保证64位原子访问，也不保证一整组字段一致。主循环采用“保存中断屏蔽状态—短临界区复制—恢复原状态”的方式读取共享记录，或使用经过验证的单生产者单消费者方案。临界区只复制必要数据，不做格式化和计算。

DMA缓冲需要明确所有权及编译器可见性，不能仅给ready标志加volatile就认为所有并发问题已解决。

## 12. 分阶段实施

1. 建立最小GD32工程，验证系统节拍、SWD、串口或LED，不先连接大幅度模拟信号。
2. 接入10MHz时基，验证CNT增长与更新频率；断开时基后确认计数停止。
3. 用3.3V、1kHz方波接PA1，实现N=1捕获和扩展时间戳。
4. 验证1Hz、0.1Hz及溢出边界，完成长周期、等待和无信号逻辑。
5. 加入时基切换、多周期、统计、保持与非阻塞显示。
6. 实现并验证高频DMA、流式累计和模式切换，覆盖100kHz。
7. 接入模拟前端，测试三种波形及输入幅度边界。
8. 校准时基、记录误差和最坏中断延迟，完成全指标验收。

第一版先交付文档；固件实施前需确定开发工具、GD32库版本、屏幕、按键引脚及DMA请求映射。不得在未查阅映射表时猜测DMA通道编号。

## 13. 验证清单

### 13.1 数值与边界

| 测试 | 条件 | 预期 |
|---|---|---|
| 基本测周 | 1kHz，10MHz档 | 每周期约10000计数 |
| 上限频率 | 100kHz，10MHz档 | 每周期约100计数，无过捕获和DMA丢样 |
| 下限频率 | 0.1Hz，10MHz档 | 每周期约100000000计数，首次可能接近20s |
| 溢出前捕获 | high=h，capture=65530，更新待处理 | 时间戳高位为h |
| 溢出后捕获 | high=h，capture=5，更新待处理 | 时间戳高位为h+1 |
| DMA跨回绕 | 前65530，后5 | 模差为11 |
| 切换时基 | 测量中修改PSC | 丢弃旧组，结果不跨档 |
| 高频变低频 | 100kHz变0.1Hz | DMA组失效，回退并重新测量 |
| 信号停止 | 捕获运行中断开 | 不继续显示伪新值，最终提示超时 |
| 缓冲/临界区压力 | 刷屏、按键、通信并行 | 不漏计、无覆盖；超限明确报错 |

软件算法可通过合成时间戳验证；硬件捕获竞争、标志清除和最坏延迟必须上板验证。测试用的故障注入可以主动长时间屏蔽中断，确认系统不会将已知无效的测量继续当作可靠结果。

### 13.2 模拟与误差

覆盖正弦、三角、方波；至少测试0.1Hz与100kHz分别配0.1Vpp与5Vpp的四个边界组合。观察比较器是否漏触发或重复触发，记录输入偏置、触发电平、信号源负载设置。

分别报告：计数步长、时基准确度、实际周期误差、短期波动、显示位数。不要仅用显示的小数位数证明达标。
